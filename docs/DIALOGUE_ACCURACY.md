# LINE の会話スレッドと日時解釈

メンションを新しい依頼の入口とし、引用返信で同じ会話を続ける。短い登録依頼と日時の指定は、LINE の送信日時と本文に基づいて確定する。[Issue #11](https://github.com/Megane14916/line-reminder-bot/issues/11)

## スレッドの扱い

- Bot へのメンションは新しいスレッドを開始する。引用付きのメンションも今回の本文を入口にする。対象タスクは本文にある名前や ID から同じグループで探す。
- Bot の操作結果や質問に引用返信したときは、引用元のメッセージ ID からスレッドを特定する。同じグループと送信者の有効なスレッドについて、最初の依頼から今回の返信の直前までを発言順に参照する。新しいメンションを挟んでも、元の Bot 返信を引用すればそのスレッドを続けられる。
- 確認待ちは10分、通常の会話は45分を基準に有効期限を管理する。期限内のスレッドは発言数による切り捨てをせず、期限切れのスレッドと履歴を Cron で削除する。引用なしの短い補足は、対象を一意に決められる確認待ちの依頼に適用する。
- 通知メッセージからの引用は、これまでどおりその通知とタスクを参照する。通知設定やタスクが引用後に変わったときは、既存のバージョン照合で確認する。

返信本文は Outbox の送信完了時に消えるため、スレッドの発言を D1 に保持する。ユーザーの実際の入力と返信本文を操作結果と同じバッチで保存し、送信済みの Bot 返信をモデルの履歴に含める。移行前の返信本文は復元できないため、保存済みの依頼や質問待ちの状態から続行できるようにする。

## 短文登録と日時

「教科書　11/22」のような明確な短文は、本文中のタスク名と日付から登録する。全角の数字・区切り・空白も受け付ける。既存タスクの変更や質問と分かる表現は、通常の意図解釈に渡す。

「明日教科書を持っていく。今日の夜に通知して」では、必要日と通知日を別々に解析する。「今日」「明日」は各発言の送信日時を日本時間に換算して確定し、元の依頼の日時を保留状態に保存する。時刻が確定する場合は返信に表示し、時刻の確認が必要なら同じスレッドで聞く。日付をまたいで時刻だけ答えた場合は元の通知日を引き継ぎ、過ぎた時刻なら再指定を案内する。

## 検証

Webhook、ローカル D1、モック LINE API を通して、返信文、タスク、通知日時まで照合する。発言数が直近5件を超えるスレッド、新規メンション、元のスレッドへの再返信、別送信者・別グループ、再配送、全角入力、年越し、日本時間の日付またぎ、過去の通知時刻を回帰ケースに加える。

実モデルは合成データで実行する。正しい対象・日時に初回で到達した件数、不要な確認、誤更新、12秒の推論制限内で完了した件数を記録する。

Gemini を使う Webhook 回帰テストは、ローカルの `.dev.vars.gemini` に設定したキーで実行できる。LINE 送信と D1 はローカルのテスト環境を使う。

```powershell
$env:RUN_REAL_GEMINI_DIALOGUE_EVAL = '1'
node --env-file=.dev.vars.gemini node_modules/vitest/vitest.mjs run tests/webhook.test.ts --exclude '**/.wrangler/**' -t 'Gemini preserves reminder dates'
Remove-Item Env:RUN_REAL_GEMINI_DIALOGUE_EVAL
```
